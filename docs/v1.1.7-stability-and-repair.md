# SHmap v1.1.7 稳定性修复说明

## 本次程序修复

- “检查数据更新”改为使用当前 GitHub 登录凭据读取私有 `a58293/SHmap-Data`，不再匿名读取公开程序仓库。
- 本机上传成功的更改包会立即按远程路径记为已同步，不再等下一次下载后才识别。
- 关闭 Tauri 窗口前强制等待最后一批 SQLite 保存完成，降低快速退出丢失编辑的风险。
- 正式母数据升级时，同时保护本轮更改、历史提交和跨设备更改包实际修改过的对象字段。
- 前端二次迁移使用同一套字段保护，避免 Rust 已经保留的数据又被浏览器层覆盖。
- 旧对象 ID 若与正式母表使用同一 `rowRef`，不再作为“本地新对象”重复追加。
- 相同内容、相同类型的备份不再重复创建。
- 自动备份只存 SQLite；手动备份和升级前等关键备份仍额外写外部 JSON。

## 数据修复预览

另附的预览更改包包含：

- 231 份连续向后错 3 行的博物志归位；
- 2 份同经篇、目标为空且证据明确的链外归位；
- 3 条相同 `rowRef` 的旧 ID 重复对象合并和删除；
- 1 份跨经篇异常继续保持不动。

该更改包不会自动写入数据库。必须先在客户端批量更改包预览界面核对逐条结果，再决定是否应用。

## 不会自动执行的操作

- 不删除现有旧备份；
- 不直接修改当前 `shmap.db`；
- 不自动清理约 2 GB 的旧数据库/备份占用；
- 不自动应用数据修复预览包；
- 不对大型 `app.js` 做高风险整体重构。
