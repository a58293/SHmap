SHmap v1.0.4 地块内容冲突预览与多选处理

本次解决冲突列表被“导入时间”等同步记录占满，以及大量冲突必须逐条选择的问题。

新增内容：
1. 导入时间、创建时间和更新时间不再作为人工冲突。
2. 冲突左右两侧显示本机地块实际内容与更改包拟写入内容。
3. 复杂档案使用直观中文字段展示，不再优先显示技术结构。
4. 每条实际内容冲突可以勾选。
5. 支持全选本页或任意多选，并统一保留本机或采用更改包。
6. 未勾选内容仍保持各自当前选择，不会被批量操作影响。

以下为 v1.0.3 功能说明：

SHmap v1.0.3 三项功能整合与精细地图图片

本次把冲突内容对照、图片图库自动保存和精细地图对象卡图片合并为一份完整更新。

新增内容：
1. 420%以上精细地图的对象预览卡，有主题图片时在文字旁显示缩略图。
2. 缩略图严格读取当前对象自己的主图，不会拿同地块其他主题的图片代替。
3. 点击缩略图查看大图；点击卡片其他位置继续打开该对象博物志。
4. 没有图片的对象保持原来的简洁文字布局，不显示占位图。
5. 完整保留冲突内容左右对照与逐字段选择。
6. 完整保留图片图库添加、删除、主图排序和说明修改的自动保存。

以下为 v1.0.2 功能说明：

SHmap v1.0.2 图片图库自动保存

本次修复图片加入图库后仍需手动保存的问题。

新增内容：
1. 添加图片并转换为WebP后立即自动保存。
2. 删除图片、设为主图后立即自动保存。
3. 图片说明、来源和版权备注停止输入约半秒后自动保存。
4. 图库窗口显示正在保存、已保存或保存失败状态。
5. 关闭窗口时会补存尚未写入的内容，不再因为忘点保存而丢失。
6. 保留v1.0.1的本机内容／更改包内容左右对照与逐字段选择。

以下为 v1.0.1 功能说明：

SHmap v1.0.1 冲突内容对照与逐字段选择

本次更新把多端冲突从“只看字段名”改成“直接看两边实际内容”。

新增内容：
1. 每个冲突字段显示“本机当前内容”和“更改包内容”。
2. dossier、profile、museumEntries 等内部字段名转换成直观中文名称。
3. 同一个对象里的多个冲突字段可以分别选择，不再整张对象卡一起替换。
4. 默认保留本机内容，明确选择后才采用更改包内容。
5. 长文本可在各自预览框内滚动；图片数据只显示体积摘要，不加载大段编码。
6. 不修改 SQLite、data.js、617条基础资料、79段水系路径或118个箭头格。

以下为 v1.0.0 功能说明：

SHmap v1.0.0 多端自动合并与逐项冲突选择

本次更新不再因为一个冲突拦截整份更改包。

新增内容：
1. 不同设备给同一对象新增不同图片时，程序自动合并并按图片内容去重。
2. 不同地块内部资料条目分别发生修改时，程序按条目逐项合并。
3. 同一图片或同一字段确实被两端改成不同结果时，单独列出冲突。
4. 每个冲突可以选择“保留本机（推荐）”或“使用更改包”。
5. 安全内容继续照常写入，不受同包其他冲突影响。
6. 单包和批量包共用同一套冲突选择逻辑。
7. 应用前继续自动建立桌面数据库备份。

以下为 v0.9.9 功能说明：

SHmap v0.9.9 顶部与地图工具分层优化

补充修复：5张或更多图片提交时不再传输膨胀的数字数组；GitHub网络异常时会自动结束等待并保留本轮，可稍后重试。
补充修复：博物志切换资料主题时同步显示该主题自己的主图；主题无图时才回退地块主体图。
补充优化：顶部操作与地图工具重新分层。导入和完成编辑保持直接可见；更新、批量更改包和导出统一放入“数据与同步”；关系、核对、测量和画笔统一放入分组清楚的“地图工具”；地图规格与使用教学归入“系统”。

本次更新解决“一个地块内有多个对象需要图片，但只能添加一张”的问题。

新增内容：
1. 每个地块保留独立的地块主体图库。
2. 同一地块内的每个独立对象可以分别拥有多张图片。
3. Markdown 第06节形成的地块内部资料条目，也可以分别拥有多张图片。
4. 每个主题均可指定一张主图，并可修改图片说明、来源和版权信息。
5. 旧版单张 imageUrl 会自动兼容为图库主图，不需要重新上传。
6. 图片仍使用现有自动 WebP 转换流程。
7. 多图资料随山海经地图更改包（.shjpatch）同步，不修改基础 data.js。

使用方法：
进入地块 → 编辑地块与对象 → 本格主题图库 → 选择地块主体或具体对象/内部条目 → 管理图库。

版本：v1.0.4
本包不包含 data.js，也不包含 SQLite 数据库。
